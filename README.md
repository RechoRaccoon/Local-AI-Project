# Raccoon AI

A local-first personal assistant, beginning with an Android prototype.

## Current milestone

This repository contains the first Flutter interface foundation:
- A custom-drawn geometric raccoon mascot.
- A conversation-ready assistant screen.
- Clear UI states for an unconfigured local model.
- A modular starting point for local inference, voice, storage, and platform integrations.
- A GitHub Actions workflow that generates the Android platform project and builds a debug APK.

**This is not yet an AI-powered assistant.** No model is bundled, no messages are sent to a cloud model, and the chat composer is intentionally not presented as functional until a local inference adapter is implemented.

## Build the Android APK

The GitHub Actions workflow runs on pushes and pull requests. It creates the standard Android runner files with Flutter, resolves dependencies, and builds a debug APK.

To build locally with Flutter installed:

```bash
flutter create . --platforms=android --project-name raccoon_ai
flutter pub get
flutter run
```

The debug APK is produced at `build/app/outputs/flutter-apk/app-debug.apk`.

## Planned architecture

- **App/UI:** Flutter and Dart.
- **Android integration:** Kotlin platform adapters, added as Android capabilities are implemented.
- **Local LLM:** llama.cpp integration, after device benchmarking.
- **Speech recognition:** evaluate whisper.cpp and Sherpa-ONNX.
- **Speech synthesis:** evaluate offline engines such as Piper, with Android compatibility and licensing verified before adoption.
- **History:** local database with platform-backed key management.
- **Mascot:** custom Flutter vector painting and animation, designed to support idle, listening, thinking, and speaking states.
- **Desktop and OBS:** later platform adapters; not part of this initial Android build.

## Privacy principles

- Local processing is the default design goal.
- No analytics or conversation telemetry are added by this starter.
- No cloud model calls are implemented.
- Model downloads and external actions must require clear user intent.
- Agent actions will need visible activity, permission checks, cancellation, and confirmation for consequential operations.
